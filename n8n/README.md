| `07-local-seo-monitor.json` | Service × location opportunities | Thu 03:00 |

## Setup
1. Create a service key: `npm run cli -- create-api-key n8n` (it can run jobs but can never approve changes).
2. Set in `.env`: `SEO_API_KEY`, `SEO_PROJECT_ID` (`npm run cli -- list-projects`). docker-compose passes them to n8n together with `SEO_API_URL=http://api:4000` and `N8N_BLOCK_ENV_ACCESS_IN_NODE=false` (workflows read them via `$env`).
3. Import: `docker compose --profile setup run --rm n8n-import` (re-run after regenerating; workflows keep fixed IDs so the error-workflow link survives).
4. In the n8n UI activate **00 Error Handler first**, then the others. No n8n credentials are needed – auth is the `x-api-key` header from env (see `credentials/README.md` if you prefer n8n credentials).

Running n8n outside docker-compose? Set the same env vars on the n8n process, or import through the UI (Workflows → Import from file).

## Editing
The JSON files are generated by `scripts/generate-workflows.mjs` (single source of truth for auth headers, retries, correlation IDs and error handling). Edit the script, run `npm run n8n:generate`, then `npm test` – `n8n/test/workflows.test.ts` validates structure, reachability, env-based auth, retries, and replays every static job payload against the real API.

## Conventions
- Every API call: `x-api-key`, `x-correlation-id: <workflow>-<executionId>`, 3 retries 30 s apart, long timeouts for crawls.
- Jobs run with `?wait=true`; a failed job returns non-2xx so n8n retries and then fails loudly → Error Handler → alert. The job's error and correlation ID are also stored in `job_runs` (Dashboard → Settings → Jobs).
- n8n never approves or publishes: approvals happen only in the dashboard by editors/admins.
